One question, end to end

A person asks their own assistant about their own proposal. What runs where, and which parts are the agent, the skill, the MCP server and the tools.

Written 2026-11-01 against main at 960c6c3a. An explainer, not a decision. Companion to problems-and-tools.html and proposed-capabilities.html.

1. The question 2. The four parts 3. The picture 4. One request, step by step 5. The calls for the budget question 6. The second way in 7. Where the flow runs out 8. Moderate is a store, not a tool

1. The question

The horizon platform may ask: "I'm interested in this grant. Find everything I'd need to specify a budget."

A staff member asking about someone else's proposal passes a proposal_id. access.ts decides from their relation to that proposal (owner, member, routed_spa, rd_pool and so on) whether they see it. A director or research staff looking at a whole group would be a new relation or role there, not a new kind of tool. That is to be specified later.

2. The four parts

The agent is the model. It runs in the person's own client and decides which tools to call and how to write the answer. horizon does not run it on this path.

The skill is a folder of instructions. It teaches judgment, not data: quote dates, keep UVM's half apart from the funder's, never call a scanned document missing. In Anthropic's terms it is "tool-first". Claude Desktop users get it separately. The MCP Skills extension (SEP-2640, Final) could serve a skill from the server, but Claude Code, Desktop and Cursor do not support it yet (modelcontextprotocol docs/extensions/client-matrix.mdx).

The MCP server is the protocol frame. It lists the tools, takes calls and sends the server instructions. It owns no data.

The tools do the work. Each reads a store and returns the envelope {status, message, ...}.

3. The picture

4. One request, step by step

  1. The client sends POST /mcp with Authorization: Bearer hzp_....
  2. The guard requireAgentToken (guards.ts) turns the token into an Actor, or answers 401 with WWW-Authenticate.
  3. endpoint.ts takes one of the account's in-flight slots, checks the body size and charges the account's bucket by the tool's cost.
  4. connector.ts and server.ts pick the protocol era.
  5. callTool(name, input, ctx) runs with ctx = {actor, db, corpus, via: 'assistant'}.
  6. Inside callTool the branch is chosen. The doc comment just above export async function callTool in app/registry.ts lists steps 0 to 5.
  7. The reply goes back as the envelope.

The tier boundary is the seam between the two kinds of store. The published side never learns who asks. The app joins account data onto a published answer in its own process, under the account's access rules.

6. The second way in

The platform's own Ask tabs and pages call the same callTool with via: 'platform': the Ask tab, the drafter, answer/ and the pipeline page (decision 0023 addendum, item 8, in decisions/0023-one-tool-layer.md). Same tools, same checks. The difference is that there the app runs the model itself.

7. Where the flow runs out

After step 6 the agent can say what a budget must hold: the funder's caps and forms, UVM's rates with their dates, any draft. It cannot build or check one. Budgets exist only as a checklist item category ('budget' in schema.ts) or an uploaded file. There is no get_budget, no get_rates that returns numbers, no check_budget and no list_comparable_awards. See records, not passages.

8. Moderate is a store, not a tool

Decision 0023, item 3, says the tier is a property of the store, not the tool. checklist_read is Low with call_id and Moderate with proposal_id. A documents call reads published text and staff uploads together. What Moderate protects is on the data side: which Postgres role reads (mcp for published stores, web_app with the party rule for account data) and what reaches a Low store. Item 4: no account id, role, unit or token digest, held by tests at the store.

Yet the code still has two tool shapes. Published tools are the Tool type (tool.ts: name, title, description, input, output, annotations, meta, cost, handler(args, PublicCtx)). Account tools are a Contract (account/contract.ts: no output, no annotations; it adds flag, writes, own, answered). Its handler is wrapped by moderate() into a ModerateTool in app/registry.ts.
